# UI7 路径连续性与绕障恢复修复

## 适用范围与现场结论

适用分支：`codex/navigation-environment-snapshots`。修改范围为 Nav2 Controller
接入、UI7 BT、Worker 通信与 NeuPAN 绕障；未修改 CogNav、UI8、底盘驱动、机械臂驱动。

此前现场已观察到机器人能够移动，但速度低、运动间断，随后再次停止。
停车采样中定位 READY、Worker RUNNING、最终 Guard 已放行，NeuPAN 持续返回
`stop=true / bypass_valid=false / bypass_phase=final`，距目标约 1.01 m。
原路径同时报告 route_clear。该现象不能直接解释为最终 collision check 过于保守。

本次修复未调整速度上限、避障距离或故障超时阈值。**独立构建、数据检查和隔离测试
不等于实机验收通过；最终路径质量、速度、通行能力和停车距离仍须现场验证。**

## 行为变化

1. 同一已接收导航请求的路径重规划通过绑定当前 FollowPath 身份的
   `/update_follow_path` 接口更新，不再每秒结束执行并重新授权。时间戳变化不会
   单独触发更新。实际路径变化继续通过原有路径筛选、版本更新和 Guard 握手。
2. Controller 的控制循环应用更新；服务回调只校验身份、终点和几何并排入最新路径。
   队列在执行结束时清除。更新保留 goal checker 状态，取消/故障/真正的新目标仍
   按既有流程停车并结束身份。服务接收回执不等于运动许可。
3. 原路径持续畅通至少 0.6 s，机器人距路径不超过 0.15 m、朝向误差不超过
   0.35 rad、路径匹配无歧义且参考轨迹通过现有几何净空检查时，退出绕障。
4. 机器人仍在路径侧方时，只在旋转、平移、再次对齐的连接轨迹通过机器人多边形
   扫掠检查后，选取路径前方接回点。不能以终点直连代替全局路径跟踪。
5. `final` 阶段先朝向位置目标，允许安全的原地转向按朝向改善量通过进展检查。
   各候选报告求解异常、净空、首步运动量、进展量和具体拒绝原因。
6. 连续无有效候选 0.8 s 后允许重建引导，最多两次；继续无解则报告
   `bypass_recovery_exhausted`。等待不再误报 CLEAR，现有进度检查器按有界不可行
   流程退出，上层 BT 最多执行原来允许的一次重规划重试。致命故障不自动恢复。

## 接口与协作约束

`UpdatePath` 为新增的可选接口。请求包含服务端启动身份、已接收的 FollowPath UUID
和新路径；终点变化必须使用新 FollowPath。接口不创建任务、不 arm、不清除故障。
使用者必须继续持有当前 action，履行 owner 续租及取消义务。

CogNav 当前代码未修改，原有直接 FollowPath 方式仍保留新 UUID 的抢占语义。
CogNav 接入应遵循 `COGNAV_NAVIGATION_HANDOFF_20261029.md` 和
`packages/navigation_neupan_bridge/EXECUTION_OWNERSHIP.md`，不得自行发布伪造的
Worker 结果、执行上下文或 Guard 授权。不得混用新旧 runtime、Controller 和 BT 插件。

UI7 BT 使用与已接受路径配对的 parent pose/poses 区分更新；内容及 header 完全相同
的重复请求无法仅靠这些端口区分。要求独立执行时，需先取消并等待结束，或使用新的
带时间戳父请求。取消后重发始终建立新执行。

## 最小现场验收

先在空旷短路径检查周期性顿挫是否消失，再检查单障碍绕行和接回原路径；最后检查
真实受阻、取消和新目标。比较最终速度零值占比、路径更新前后执行 UUID、候选拒绝
原因、路径版本和求解时延。现场人员控制急停；维护程序不主动发送导航目标。
