# UI7 通道诊断语义修正

2026-11-02。仅修改诊断节点；不改变 NeuPAN、速度控制、停车或任务恢复。

原算法将路径切向作为前方轴，取前方探测条带中所有扫描点的横向极值，再减去整个机器人轮廓的横向极值。两个极值可能来自不同前后位置，既未拟合成对侧壁，也未在同一截面比较。弯曲路径、前方障碍、突出的机械臂均可能使其与车体左右实际空隙不符。原 `ROUTE_TOO_CLOSE`、`TOO_NARROW` 不是可靠的可通行性结论。该节点不参与停车，不能据此解释实机停滞根因。

修正采用 `r1_passage_clearance_v2`：

- 旧投影字段改为 `route_projected_left_margin_m`、`route_projected_right_margin_m` 和 `route_projected_span_m`，显示 `PROJECTION_ONLY`，明确 `diagnostic_only=true`。
- 新增 `robot_left_sampled_margin_m`、`robot_right_sampled_margin_m`：在 base_link 中，对扫描点所在 x 截面计算完整轮廓上下边界，再求横向差，分左右取最小值。前后超出轮廓范围的点不冒充侧向空隙，缺少有效采样的一侧输出 null。
- 该值仍是二维扫描的采样余量，不是三维最短距离、侧壁拟合或安全通过证明。允许保留负值表示采样与截面轮廓重叠，不对负数截零掩盖问题。
- 轮廓坐标系显式变换；空 frame 拒绝；TF 使用扫描时刻。扫描、路径和轮廓时间戳超过默认 2 秒或明显在未来则 WAIT，清除旧标记，避免任务结束后持续解读旧路径。

验证：3 个 C++ 几何回归用例覆盖对称空隙、不同 x 位置的轮廓突出误报、缺失侧和真实有符号重叠；诊断可执行文件单独编译。隔离 ROS 域 192 检查发布 JSON 的对称余量和过期 WAIT。未修改不可变发布包，未切换或重启实机节点。
