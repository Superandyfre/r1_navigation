# UI7 同任务路径无停顿交接：实现约束

当前运行协议把同一任务的新路径当成新 grant，PREPARE 时立即失效旧结果、清空原始
及平滑速度，并要求两条流各自观察到零后才能 COMMIT。隔离真实求解链中两次路径更新
分别造成约 0.60 秒和 0.52 秒最终零速。用户要求短暂交接期间沿用仍可信的旧状态；
仅仅取消零速检查会让未带任务身份的 Twist 尾迹混入新执行，不能满足撤销和防重放。

## 所需协议

1. 仅同一 authority、Controller、attempt、Worker boot/generation 的路径版本递增允许
   交接；新目标、取消、故障和未经授权换代绝不允许续用旧结果。
2. PREPARE 可保存上一次已提交结果的不可变快照；只在其原始采样、求解和发布时刻
   均未超过现有期限，健康及授权仍有效时继续，重复包、心跳和新 PREPARE 不刷新它。
3. Worker 并行地接收新路径并生成新结果；必须保持原始版本、请求号、扫描和任务身份，
   不得将旧结果重标成新结果。新结果不可用时旧结果过期后应停止并有界结束当前任务。
4. 未带身份的速度平滑输出不能直接与新 grant 等同：只有已确认的旧来源和新来源
   对应的线／角目标完全一致，且原始速度确实与目标一致时，才可把相同目标平滑地
   交给新 grant；其他情况继续使用零速尾迹屏障。不能凭相同方向或近似数值假设轨迹安全。
5. 必须在最终 Guard 独立执行前述检查；Controller 只能提出交接，不能自行授权。
   取消或 Worker 故障可在交接任何时刻立即撤销；途经状态和终态均可观察。

## 验收

覆盖相同命令无零速交接、不同命令回退屏障、旧结果到期、重复包、旧任务结果迟到、
取消/抢占/故障、多个连续路径修订、授权与心跳丢失、平滑器延迟、注入新障碍和新旧
来源乱序。分别验证真实 Controller、Worker、Guard 与平滑器的完整链；最终控制 topic
保持独立，不接机器人。现有源代码尚未实现此协议，不能把本文当成已完成。
